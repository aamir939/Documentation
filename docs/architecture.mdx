# Architecture & Technology Stack

## Platform Component Map

Dflair AI is built on a modern, microservices-based architecture designed for scalability, reliability, and security.

| Layer | Components | Technology |
|-------|------------|------------|
| **Portal & API** | Orchestration UI, REST APIs, WebSocket status | React, Python, Go, PostgreSQL, MongoDB, Redis |
| **Identity & Access** | Authentication, authorization, tenant management | Keycloak (OAuth2/OIDC), JWT, RBAC + ABAC |
| **Compute Orchestration** | Cluster lifecycle, workload management | Kubernetes (kubeadm), Slurm (Slinky Operator) |
| **Network Fabric** | Tenant isolation, VLAN/VRF management | Network Fabric Controller, VXLAN/EVPN, InfiniBand Fabric Manager |
| **Storage** | High-performance GPU storage + platform storage | High-performance parallel filesystem (Lustre/IB), Platform object storage (CSI/S3) |
| **GPU Runtime** | GPU access, telemetry, scheduling | Multi-vendor GPU Operators (NVIDIA, AMD ROCm, Intel) |
| **Monitoring** | Metrics, alerting, dashboards | VictoriaMetrics, Prometheus, Grafana |
| **Billing** | Usage tracking, quota enforcement, reporting | metering-service, PostgreSQL |
| **Container Runtime** | Container lifecycle on bare metal | containerd, runc, OCI-compliant |

## Key Microservices

### Core Services

| Service | Responsibility |
|---------|----------------|
| **bare-metal-provisioning-service** | Bare metal provisioning — translates portal requests into provisioning controller API calls |
| **workflow-engine** | Workflow orchestrator — handles provisioning logic, scheduling, and step sequencing |
| **cluster-lifecycle-service** | Kubernetes and Slurm cluster lifecycle management |
| **network-orchestration-service** | Interfaces with Network Fabric Controller for VRF/VLAN operations |
| **storage-provisioning-service** | Parallel filesystem provisioning — directories, NodeMaps, quotas |

### Platform Services

| Service | Responsibility |
|---------|----------------|
| **identity-service** | Keycloak integration for multi-tenant RBAC/ABAC enforcement |
| **metering-service** | Usage aggregation, billing calculation, quota tracking |
| **metrics-aggregation-service** | Kubernetes metrics processing for tenant clusters |
| **container-registry** | Internal image registry for air-gapped deployments |

## Network Architecture

### Dual-Fabric Design

Dflair AI uses a dual-fabric network architecture:

| Fabric | Purpose | Speed | Protocol |
|--------|---------|-------|----------|
| **Ethernet** | Management, platform services | 25G | TCP/IP, VXLAN/EVPN |
| **InfiniBand** | GPU-to-GPU, GPU-to-storage | 400G × N | RDMA, GPU collective libraries |

## High Availability Design

### Control Plane HA

| Component | HA Strategy |
|-----------|-------------|
| Portal | Multiple replicas behind HAProxy |
| Keycloak | Clustered with session replication |
| PostgreSQL | Primary-replica with automatic failover |
| etcd | 3 or 5 node quorum |
| VictoriaMetrics | HA cluster with replication |

### Data Protection

- Automated backups every 6 hours to platform object storage
- S3 lifecycle rules for archival (12–24 months retention)
- VictoriaMetrics replication for metrics durability
