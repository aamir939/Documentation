# High-Performance Storage

**Business Value:** GPU workloads are only as fast as their data pipeline. Dflair AI delivers storage throughput that keeps up with the most demanding training jobs — leveraging the full bandwidth of the InfiniBand fabric.

## Two Storage Systems, Optimized for Purpose

| System | Technology | Connection | Purpose |
|--------|------------|------------|---------|
| **Parallel Filesystem** | Lustre parallel filesystem | InfiniBand (400G × multiple links per node) | Training datasets, model checkpoints, experiment results |
| **Platform Object Storage** | Unified file/object storage | Ethernet (25G) | Platform services (databases, backups, logs, container registry) |

## Storage Security — Double Isolation

Tenant storage isolation is enforced at **two independent layers** simultaneously:

### Layer 1: InfiniBand Level (PKey)

<Drawio content={ibPkeyIsolation} />

Only the tenant's GPU ports can communicate on the tenant's IB partition.

### Layer 2: Lustre Level (NodeMap)

<Drawio content={nodemapCheck} />

Only the tenant's IB IP addresses can mount the tenant's directory.

### Defense in Depth

:::tip Security Guarantee
Even if one layer were compromised, the other would still block unauthorized access.
:::

## Using Storage

### Kubernetes Workloads

Storage is automatically mounted in pods:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: training-job
spec:
  containers:
  - name: trainer
    image: training-image:latest
    volumeMounts:
    - name: training-data
      mountPath: /data
    - name: checkpoints
      mountPath: /checkpoints
  volumes:
  - name: training-data
    persistentVolumeClaim:
      claimName: training-data-pvc
  - name: checkpoints
    persistentVolumeClaim:
      claimName: checkpoints-pvc
```

### Slurm Workloads

Lustre is mounted on all compute nodes:

```bash
#!/bin/bash
#SBATCH --job-name=training
#SBATCH --gres=gpu:8

# Training data available at mounted path
python train.py \
  --data /lustre/tenants/$TENANT/datasets/imagenet \
  --checkpoint-dir /lustre/tenants/$TENANT/checkpoints/$SLURM_JOB_ID
```

## Storage Best Practices

### Training Data Organization

```
/lustre/tenants/{tenant}/
├── datasets/
│   ├── imagenet/
│   ├── custom_data_v1/
│   └── custom_data_v2/
├── checkpoints/
│   ├── experiment_001/
│   └── experiment_002/
├── models/
│   ├── trained_model_v1/
│   └── trained_model_v2/
└── logs/
    └── tensorboard/
```

### Checkpoint Strategy

| Frequency | Purpose |
|-----------|---------|
| Every N steps | Resume from recent state |
| Best validation | Keep best performing model |
| End of epoch | Regular milestone |

### Data Loading Optimization

- Use **multiple data loader workers** to saturate I/O
- **Prefetch data** to overlap compute and I/O
- Consider **caching** for repeatedly accessed data
- Use **appropriate batch sizes** for efficient reads
